Use Case Batch registration
Author San Isidro Poultry Farm project team
Primary Actor Farm Owner
Trigger (Primary) A new flock arrives or a new production cycle must be opened in the system.
Basic Flow (Primary)
  1. Admin signs in and opens batch registration.
  2. Admin enters batch code, arrival date, initial head count, and supplier.
  3. Admin submits the form.
  4. The system adds the batch and shows it on the home batch list with current stock.
Post Condition (Primary) The batch is stored and available for monitoring, activity logging, and related workflows.
Secondary Actor Farm Worker
Trigger (Secondary) Worker opens the home page or any screen that lists batches for daily work.
Basic Flow (Secondary)
  1. Worker views the batch list (code, arrival date, stock, status).
  2. Worker selects this batch when logging activities, mortality, or tasks tied to a batch.
Post Condition (Secondary) Field work is linked to the registered batch; counts stay aligned with what the admin entered.
